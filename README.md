# MOA

한양대·왕십리 카페의 스탬프와 쿠폰을 한곳에서 보는 테스트용 멤버십 앱입니다. 매장 이름, 영업시간, 메뉴, 가격, 보상과 지도 배치는 시연 데이터입니다.

현재 Android 버전은 **0.6.0**입니다. [통합판 벤치마크와 구현 결과](MOA-통합판-벤치마크와구현.md)에 앞선 공식 자료 비교와 구현 범위를 정리했습니다. 이번 재방문 관리 개선은 아래에 설명합니다.

## 이번 개선

- **점주 오늘의 고객 관리**: 첫 이용 후 7일 이상 다시 이용하지 않은 고객과, 이용일 2일 이상이면서 마지막 이용 후 21일 이상 지난 고객을 구분합니다. MOA 적립·혜택 사용·픽업 완료를 한국 시간 같은 날 1일로 합칩니다. 취소 거래와 타 매장 기록은 제외하며 실제 첫 방문이나 추가 매출로 단정하지 않습니다. 신규 픽업은 완료 시각을 보관하고 과거 기록은 적립·사용 확인 시각을 우선합니다. 완료 시각이 없는 과거 주문은 원래 요청 시각을 사용합니다.
- **고객 카페별 혜택 수신**: 마이 → 수신 설정 관리, 또는 매장 메뉴의 혜택 수신 설정에서 매장별 앱 내 맞춤 혜택을 선택합니다. 기본은 받지 않음이며 변경 이력을 저장합니다. 문자·카카오톡 동의를 대신하지 않습니다. 철회해도 기본 적립과 발급된 쿠폰은 유지합니다.
- **내 카페의 초대**: 무료 프로 파일럿을 시작한 점주는 조건과 수신 동의를 만족하는 고객에게 재방문 혜택을 등록합니다. 대상은 서버가 계산하며 공개 카탈로그와 다른 고객에게 노출하지 않습니다. 이후 이용 기록이 있거나 동의를 철회하면 미수령 초대를 숨깁니다. 받은 쿠폰은 기존 쿠폰함·QR·픽업 경로로 사용합니다. 재방문 혜택의 유입 수수료는 0원입니다.
- **30일 프로 무료 파일럿**: 점주가 조건을 확인하고 시작합니다. 자동 결제나 실제 구독 청구는 없으며 재시도로 기간을 늘릴 수 없습니다. 종료 후 새로운 재방문 혜택 등록·미수령 발급은 제한하고 기존 발급 쿠폰은 보장합니다. 실제 유료화·가격 확정은 별도 검증 단계입니다.
- **특가 운영 조건**: 매일/평일/주말, 한국 시간 시작·종료, 하루 발급 한도, 총 발급 수량·예산을 함께 검증합니다. 시간은 같은 날 안에서 설정합니다. 발급·직접 사용·픽업 견적에서 조건을 확인하며, 이미 접수된 픽업은 요청 시각의 조건을 적용합니다. 하루 한도는 사용 수가 아닌 발급 수입니다.
- **비용 확인**: 메뉴 변동비를 입력하면 할인·수수료 반영 후 잔당 공헌이익 추정과 설정한 최소 금액을 확인합니다. 최소 금액 미달은 서버에서도 차단합니다. 사용분 합계는 관측한 대상 메뉴의 추정치이며 추가 매출·순이익이 아닙니다. 기관 지원은 지원금 수령을 가정하며 입금을 검증하지 않습니다.
- **화면 정리**: 고객 홈의 개인 초대를 한 번만 표시하고 네 개 하단 메뉴를 유지합니다. 점주 화면 상단에 고객 관리와 적립·픽업 바로가기를 배치했습니다. 로열 블루 `#0046C7`, Pretendard와 기존 사진·여백을 유지합니다. 시연 고객 3명은 브라우저/APK의 체험 모드에만 생성합니다.

### 재방문 기능의 데이터와 API

기존 SQLite 단일 상태의 트랜잭션 구조와 공통 캠페인·쿠폰 도메인을 재사용합니다. 기존 적립·회원·키링·점주 서버 설정을 초기화하지 않습니다.

| 항목 | 추가 내용 |
| --- | --- |
| `/api/member` | `storeConsent` — 현재 회원의 매장별 앱 내 수신 설정 변경 |
| `/api/counter` | `retentionTrial` — 인증된 현재 매장의 무료 파일럿 시작 |
| 기존 `overview` | 매장별 재방문 집계·세그먼트·파일럿 상태. 고객 목록은 유효 파일럿에서만 제공 |
| 기존 캠페인 API | `type: return`, `segment: second/lapsed`. 대상 고객은 서버에서 선정 |
| 회원 | `storeConsents`, `consentHistory` — 매장·범위·버전·선택 시각 |
| 서버 | `retentionTrials` — 매장별 시작·만료·조건 버전 |
| 캠페인·쿠폰 | 요일·시간·하루 발급 수량, 캠페인의 변동비·최소 공헌이익·재방문 대상. 대상 명단과 비용은 고객 응답에 제외 |
| 픽업 | `pickedUpAt` — 실제 점주 완료 처리 시각 |

변경 파일은 `www/retention.mjs`, `www/core.mjs`, `www/campaigns.mjs`, `www/checkout.mjs`, `www/app.mjs`, `www/views.mjs`, `www/style.css`, `server.mjs`, `build-android.ps1`, `android/AndroidManifest.xml`, 이 README와 `tests/retention.test.mjs`, `tests/http.test.mjs`, `tests/retention-browser.cjs`, `tests/android-bundle.cjs`입니다.

`node --test tests/*.test.mjs`에서 기존 회귀·재방문·동의·시간 조건·원가 제한·두 서버 동시성·지속성을 검사합니다. 추가 브라우저 검사 `tests/retention-browser.cjs`는 별도 `retention-qa-*.sqlite`와 `MOA_TEST_DATABASE`가 필요하며 실제 매장 DB를 대상으로 실행하지 않습니다. `tests/android-bundle.cjs`는 `MOA_PACKAGED_HTML`에 빌드된 `android/res/raw/taggo_page.html`을 지정해 실제 APK 내장 페이지의 브리지 모의 연결·동의·파일럿을 검사합니다. 공통 Playwright 환경은 기존 검증 절차와 같습니다.

후속 운영 개발은 중앙 입점·직원 인증·외부 메시지 발송과 별도 동의, 실제 구독 결제·계약, 비교군을 통한 추가 구매 효과 검증입니다. 현재 앱 내 혜택은 앱을 열었을 때 조회하는 방식으로 앱 밖의 고객에게 재방문 메시지를 보내지 않습니다.

### 기존 고객 기능

- **홈 상단 오늘의 카페 혜택**: 매장·메뉴·할인 전후 가격·최소 구매액·기간·수량을 첫 화면에서 확인해요. 카페 이름을 눌러 최대 세 가지 혜택을 비교하고 바로 쿠폰을 받거나 보유 쿠폰함으로 이동할 수 있어요. 첫 방문·기관 코드는 조건을 표시하고 만료·품절·소진·이미 사용한 혜택은 추천에서 제외합니다. 일반 타임딜을 먼저 보여주며 실제 발행 혜택이 없으면 기존 홈을 유지해요. 체험 모드는 만료된 시연 캠페인을 새로 만들되 이전 쿠폰이나 사용 기록을 연장·초기화하지 않습니다.
- **주문할 때 쿠폰 적용**: 현재 담은 메뉴와 최소 구매액을 확인해 가장 큰 할인 보유 쿠폰을 먼저 제안해요. 사용 안 함이나 다른 쿠폰도 선택할 수 있어요. 메뉴 금액·할인·매장 결제 금액·적립 예정 수량을 분리합니다.
- **실제 픽업에서 쿠폰 사용**: 요청할 때는 쿠폰을 예약하고 점주의 결제·픽업 확인 때 사용·수수료 산정·적립을 함께 처리해요. 같은 쿠폰을 다른 주문이나 QR에서 다시 사용할 수 없습니다. 주문을 취소하면 유효기간이 남은 쿠폰을 다시 쓸 수 있어요.
- **나의 메뉴**: 담은 구성이나 완료한 주문을 이름을 붙여 최대 12개 저장해요. 요청사항도 함께 저장하며, 담을 때 현재 가격·품절을 다시 확인해요. 홈·매장 메뉴·마이에서 사용할 수 있고 서버 계정의 복구 후에도 보관합니다.
- **가입 전 탐색**: 가입 화면에서 카페를 먼저 둘러보고 이용할 수 있어요. 기존 네 개 하단 메뉴를 유지합니다.
- 홈과 쿠폰함에서 선택 쿠폰의 **사용 QR**을 바로 열어요. 점주는 조회하면 해당 쿠폰 확인 창으로 연결됩니다.
- 완성에 가까운 스탬프북을 먼저 보여주며, **쿠폰함 → 스탬프북**에서 전체 카페를 볼 수 있어요. 매장·쿠폰 종류 필터도 제공합니다.
- **주변 카페 → 혜택 모아보기**에서 받을 수 있는 혜택·즐겨찾는 카페·혜택 종류·검색 조건을 함께 사용해요. 할인 후 가격과 구매 조건, 기관 참여 코드 필요 여부를 미리 확인합니다.
- 완료 주문의 **다시 담기**는 현재 가격·품절을 확인해 메뉴에 담아요. 최종 픽업 요청은 따로 보내며, 요청사항과 네 단계 진행 상태를 점주·고객이 함께 확인합니다.
- 체험 모드에는 다시 담기를 시험할 완료 주문이 한 건 있어요. 실제 서버 계정에 시연 주문을 생성하지 않습니다.

## 실행

- Android 8 이상에서는 `dist/MOA-Android.apk`를 설치해요. 기존 Tag&Go 테스트 앱이 있으면 같은 앱의 업데이트로 설치할 수 있습니다.
- Windows에서 `Start-TagAndGo.cmd`를 실행하면 콘솔에 주소와 점주 PIN이 표시됩니다. Node.js 22.13 이상 또는 Codex에 포함된 Node.js를 사용합니다.
- PC에서 [고객 체험 화면](http://localhost:8787/), [서버에 연결된 고객 화면](http://localhost:8787/?live=1), [점주 POS](http://localhost:8787/?pos=1)를 열 수 있습니다.
- 휴대폰을 PC 서버에 연결하려면 두 기기를 같은 와이파이에 연결하세요. 앱의 **마이 → 테스트 서버 연결**에 콘솔에 표시된 휴대폰용 IPv4 주소를 입력하고 닉네임으로 시작하면 됩니다. 서버 창은 테스트가 끝날 때까지 열어 둡니다.

## 점주가 자기 매장 테스트 서버 만들기

1. 서버로 사용할 Windows PC에서 `Start-MOA-Store.cmd`를 엽니다. Node.js 22.13 이상이 필요하며, 이 PC에서는 Codex에 포함된 Node.js도 사용합니다.
2. 같은 PC에서 [점주 설정](http://localhost:8890/setup)을 엽니다. 매장명·지역·영업시간, 1~20개 스탬프 기준과 메뉴를 입력합니다. 첫 메뉴는 무료 적립 보상으로 제공할 음료입니다.
3. **내 매장 테스트 서버 만들기**를 누르면 점주 PIN, 점주 POS 링크와 고객 접속 QR이 나타납니다. PIN은 고객에게 공유하는 QR에 포함되지 않습니다.
4. 점주는 **점주 POS 열기**에서 발급된 PIN으로 로그인하고, 고객은 같은 와이파이의 휴대폰으로 QR을 읽어 닉네임으로 시작합니다. 휴대폰에서는 PC용 localhost 주소 대신 설정 화면에 나온 와이파이 주소를 사용합니다.
5. Android에서는 v0.3.1 이상의 APK를 설치하고 **마이 → 테스트 서버 연결**에 설정 화면의 앱 서버 주소를 입력합니다. 직접 입력한 매장·메뉴·적립 기준이 표시됩니다.

점주 서버 데이터와 PIN 해시는 `data/merchant-test.sqlite`에 저장합니다. PC를 다시 켜도 같은 실행 파일로 기존 매장과 적립 기록을 이어갑니다. PIN을 잊으면 서버 PC의 설정 화면에서 다시 발급할 수 있고 이전 점주 세션은 해제됩니다. 설정 변경은 서버 PC의 localhost 화면에서만 처리합니다.

이 구성은 PC를 켜 두고 같은 와이파이에서 사용하는 매장 1곳의 테스트 서버입니다. 외부 인터넷용 배포와 PC 방화벽·공유기 설정 변경은 별도입니다. 휴대폰 실기기와 실물 NFC 검증은 별도로 진행합니다. 기존 8787 데모 서버와 데이터 파일은 분리합니다.

## 고객과 점주 흐름

| 기능 | 이용 방법 |
| --- | --- |
| 키링 등록·적립 | 고객은 **마이 → 내 키링**에서 연결 코드를 확인합니다. 직원은 POS에서 키링을 읽고 연결 코드를 입력한 뒤 결제 내역을 확인해 적립을 승인합니다. |
| QR 대체 | 고객은 홈에서 **매장에 보여줄 QR**을 누릅니다. 직원은 키보드 방식 USB QR 스캐너로 읽거나 POS에 표시된 문자열을 직접 입력합니다. QR은 2분 이내에 적립이나 쿠폰 사용 한 건에 쓸 수 있어요. |
| 쿠폰·만료 안내 | 쿠폰함은 사용 가능과 지난 쿠폰을 나누고 가까운 만료일을 먼저 보여줘요. **마이 → 쿠폰 만료 안내**에서 앱 화면에 표시할 1·3·7일 기준을 설정할 수 있습니다. |
| 사후 적립·취소 | 직원은 실제 결제를 확인한 뒤 사후 적립 코드를 발행합니다. 고객은 홈에서 코드를 입력해 7일 이내 한 번 적립할 수 있어요. 최근 적립 취소는 같은 매장·고객의 24시간 내 마지막 적립부터 가능하며, 이미 사용한 쿠폰이 걸린 경우에는 취소를 막습니다. |
| 픽업 | 매장 메뉴에서 수량을 담아 픽업을 요청합니다. 테스트 POS는 접수·제조·준비·픽업 상태를 관리해요. 매장에서 결제하고 픽업한 주문의 음료만 적립됩니다. |
| 계정 복구 | 서버에 연결된 계정은 **마이**에서 복구 키를 발급하고 같은 서버에 연결된 새 기기에서 복구할 수 있습니다. 복구하면 이전 기기의 연결이 만료됩니다. 키링을 분실한 경우에는 기존 키링을 잠근 뒤 매장에서 새 키링으로 교체할 수 있어요. |

체험 모드에서는 **마이 → 점주 POS → POS 열기 → 체험 키링 태그**로 적립을 해볼 수 있습니다. 휴대폰 앱의 점주 화면에서는 기기에 NFC가 있을 때 **휴대폰 NFC로 읽기**도 사용할 수 있어요. PC에서는 UID를 키보드로 출력하는 리더기의 끝 문자로 Enter를 설정하세요. PC/SC 전용 리더기는 별도 연결 프로그램이 필요합니다. Android와 USB 리더를 같이 쓸 경우 UID의 16진수 출력과 바이트 순서를 맞춰야 합니다.

## 현재 범위

점주 지표는 MOA 적립·쿠폰·캠페인 사용 데이터에서 계산한 값입니다. 현재 서버는 같은 네트워크에서 시험하는 용도이며, 데이터는 SQLite `data/pilot.sqlite`에 저장됩니다. 최초 시작 시 기존 `data/pilot.json`을 가져오고 원본을 보존합니다. 앱 안에서 만료를 안내합니다. 운영용 클라우드·직원별 계정, 소셜 로그인, 푸시 알림, GPS 지도, 실결제 및 포스 연동, 매장 간 공동 정산과 외부 상품권은 별도 단계입니다.

## 빌드

Android SDK 플랫폼 35, Build Tools 35.0.0, JDK 17 환경에서 `build-android.ps1 -SdkRoot <SDK 경로> -JdkRoot <JDK 경로>`를 실행합니다. Android 빌드는 `www`의 화면과 이미지, QR 생성기를 내장합니다. QR 생성기의 MIT 라이선스는 [qrcode-LICENSE.txt](www/qrcode-LICENSE.txt)에 있습니다.

Pretendard 가변 글꼴은 웹과 APK에 함께 포함합니다. [원본 글꼴](https://github.com/orioncactus/pretendard)과 [SIL Open Font License](www/fonts/Pretendard-LICENSE.txt)를 확인할 수 있습니다. 키링은 마이 화면의 디자인 시안입니다. 적립이 완료되면 블루 스탬프 애니메이션과 짧은 햅틱 피드백을 제공하며, 진동은 기기와 시스템 설정에 따라 동작합니다.

홈 사진은 [Nathan Dumlao의 white ceramic teacup on saucer](https://unsplash.com/photos/white-ceramic-teacup-on-saucer-l59fmhtprIE)를 사용하며 [Unsplash License](https://unsplash.com/license)에 따라 앱에 포함합니다. 제휴 매장 자체 사진은 별도 촬영 자료가 필요합니다.

## 캠페인 사용

홈의 스탬프 아래 **오늘의 혜택**과 매장 상세에서 첫 방문·타임딜·기관 지원 쿠폰을 받아 기존 쿠폰함에서 사용합니다. **마이 → 점주 POS**의 캠페인 관리에서 등록·수정·발급 종료와 예산·성과를 확인합니다. 실제 서버에는 점주가 캠페인을 등록해야 합니다.

체험 모드의 기관 참여 코드는 **MOADEMO26**입니다. 실제 사용 승인은 직원이 NFC 또는 QR로 고객을 조회하고, 날짜 포함 영수증 번호와 대상 메뉴·구매 금액을 확인한 뒤 처리합니다. 유상 대상 음료는 1잔 자동 적립되므로 같은 음료를 별도로 다시 적립하지 않습니다. 첫 방문은 MOA 계정 기록과 직원 확인을 함께 사용합니다.

개발용 POS는 기존 공용 PIN을 사용하며 세션은 선택한 매장에 고정됩니다. 실제 영업용 직원·사업자 인증과 외부 POS·결제 연동은 후속 단계입니다. 수수료 산정액은 청구·입금 완료 금액과 구분됩니다.
